# 我的旅行筆記

繁體中文的個人旅遊分享網站，以原本 `assets/` 裡六個地點的照片與遊記為內容。

## 如何開啟

直接用瀏覽器開啟 `index.html`。不需要安裝套件，也沒有建置指令。

網站只有四個 HTML、一份共用 CSS、一份原生 JavaScript，以及本機照片。所有頁面連結都使用相對路徑，可放在 GitHub Pages 的專案目錄下。

## 三個互動怎麼解釋

### 1. 閱讀建議

按鈕的 `onclick` 呼叫 `chooseTrip()`，並傳入 `city` 或 `mountain`。函式用 `getElementById()` 找到結果段落與連結；`if / else` 判斷類型，再修改 `textContent` 和連結的 `href`。用途是幫讀者挑選遊記，不會呼叫網路服務。

### 2. 旅費試算

表單送出時呼叫 `calculateBudget()`；`return false` 防止表單造成頁面重新載入。函式讀取四個輸入欄位的 `.value`，用 `Number()` 轉成數字，檢查數值後計算：

`每人總額 = (天數 − 1) × 每晚住宿 + 天數 × 每日餐費 + 整趟交通`

例如 3 天、住宿 1000、每日餐費 500、交通 1200，**應得到 NT$ 4,700**。金額都是每人新臺幣；不會自動換匯。預設金額是示範，並非實際旅費紀錄。

### 3. 登山用品勾選清單

從提供的裝備資料挑出並整理成 12 項，分為「行走與聯絡、衣物與鞋子、補給與隨身用品」。精簡清單以單日健行作為整理起點，多日、雪季或特殊路線仍需增加所需裝備。

核取方塊使用 `input type="checkbox"`；外層 `label` 讓讀者點文字也能勾選。表單的 `onchange` 在勾選狀態改變時呼叫 `updateChecklist()`。

函式用 `getElementsByName("hiking-gear")` 取得用品，用 `for` 迴圈依序查看 `.checked`；每勾一項就累加數量，再用 `textContent` 更新「已準備 X / 12 項」。全選時改顯示清單已全數勾選的文字。

`resetChecklist()` 將各項 `.checked` 設為 `false`，再呼叫 `updateChecklist()` 更新數量。這裡新增了基礎迴圈及核取方塊屬性的用法。沒有加入儲存功能，重新整理或離開頁面後不保留紀錄。

## 由你操作的驗證清單

依照你的要求，實際畫面與操作驗證由你完成；下列是待驗項目，不代表已測試通過。

- 從四個頁面逐一點選頂部導覽，確認都能到另外三頁。
- 確認首頁在桌面呈現兩列兩欄，手機呈現直排。
- 確認六篇遊記的 18 張照片與圖片說明正常顯示。
- 點選本頁目錄、回到頁首與回顧表的遊記連結。
- 首頁按兩個類型按鈕，確認建議文字及連結跟著變動。
- 勾選任意用品，確認已準備數量增加；取消時減少，勾選文字也可操作。
- 全部勾選時，確認顯示 12 / 12 和完成文字。
- 按「清除全部勾選」，確認核取方塊全部取消，統計回到 0 / 12。
- 旅費試算使用預設值，確認顯示 3 天 2 夜、NT$ 4,700。
- 改成 1 天，其餘同預設值，應顯示 1 天 0 夜、NT$ 1,700。
- 將費用全部填 0，應得到 NT$ 0。
- 嘗試空白、負數、0 天及小數天數，確認表單阻止無效輸入。
- 開啟三個 Google 地圖連結，確認目的城市正確。
- 在 GitHub Pages 上再做一次以上檢查，並截圖放入報告。

## 報告如何完成

`report/code-explanation.html` 是可編輯、可列印的報告來源；`output/pdf/code-explanation-draft.pdf` 是同內容的 PDF 草稿。

1. 填上姓名、學號和兩個 GitHub 網址。
2. 看懂程式，將說明改成你自己的表達。老師明確要求使用自己的話，不能直接交 AI 解說。
3. 回答報告最後的三個心得問題，寫實際遇過的困難和學習過程。
4. 依報告各截圖欄的提示放入實際畫面，刪除待補提示。
5. 用瀏覽器開啟報告 HTML，列印、另存成 PDF，作為最後繳交版本。

## GitHub Pages 繳交步驟

目前 GitHub CLI 未登入，這個目錄也沒有既有 Git 儲存庫，因此還沒有產生公開網址。可依老師教材的方式操作：

1. 在你的 GitHub 建立公開儲存庫，例如 `travel-notes`。
2. 上傳四個 HTML、`style.css`、`script.js` 和完整 `assets/`；`index.html` 要在儲存庫根目錄。需要版本控管報告時，也可上傳 `report/` 和 `output/pdf/`。
3. 在儲存庫的 Settings → Pages 選擇 Deploy from a branch、`main`、`/(root)`，儲存設定。
4. 等部署完成，從 GitHub 顯示的 Pages 連結開啟網站，再將實際網址填回報告。

`tmp/` 是製作過程中的暫存工具與 PDF 抽字，不是網站的一部分，不必上傳。原始作業 PDF、教材和照片原稿均保留。
